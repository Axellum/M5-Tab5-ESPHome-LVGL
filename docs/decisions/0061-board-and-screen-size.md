# ADR-0061: The board and the screen size are a compile-time choice (`tab5_carte`), one package per board, the size written once

**Status:** Accepted (2026-10-12, lot 1 of the Waveshare 1024×600 port; the Waveshare board compiles but has never run on a board when written).
**Date:** 2026-10-12

## Context

Axel ordered a Waveshare ESP32-P4-WIFI6-Touch-LCD-7B (1024×600, landscape panel, ESP32-P4 revision 3, 32 MB flash). The firmware assumed one board everywhere: the Tab5's hardware in `tab5-hardware.yaml` and its screen revision in `ecran-*.yaml`, `1280`/`720` written in the tokens, in `tab5_geometrie.h` and in the C++ that derives from it, `rotation: 270` in LVGL and in the pinball's return to landscape, the font sizes in pixels.

The goal of this first lot: make the board and its screen size a parameter **without changing a pixel or a behaviour on the Tab5**, and have the Waveshare firmware compile completely. Adapting the interface to 1024×600 is a later lot.

## Decision

- **One substitution, `tab5_carte`** (`Tab5/user_entities.yaml`; `tab5` by default through Jinja, like `tab5_ecran`), picks `Tab5/paquets/carte-<carte>.yaml` at the place `tab5_hardware` and `tab5_ecran` had in the `packages:` block. A board package carries the hardware **and** the geometry:
    - `carte-tab5.yaml` loads `geometrie-tab5.yaml`, `tab5-hardware.yaml` and the screen revision `ecran-*.yaml`, unchanged;
    - `carte-waveshare-7b.yaml` holds the whole hardware of the Waveshare (pins from the compiled trial `essais/waveshare-p4-7b.yaml` of the `feat/essais-ecrans-waveshare` branch) and loads `geometrie-waveshare-7b.yaml`.
- **The geometry of a board is six substitutions** in `geometrie-<carte>.yaml`: screen size in landscape (`carte_ecran_l`, `carte_ecran_h`), panel size as the display driver sees it (`carte_dalle_l`, `carte_dalle_h`), LVGL rotation (`carte_rotation`: 270 on the Tab5, whose panel is portrait; 0 on the Waveshare) and the scale of the large fonts (`carte_police_echelle`: 1, and 0.82 on the Waveshare, a little under 600 / 720 ≈ 0.83).
- **The size is written once.** The tokens derive from it (`modal_card_w: ${ carte_ecran_l | int - 30 }`, `cal_grid_h` from `modal_card_h`); the C++ gets it through `-DTAB5_ECRAN_L`, `-DTAB5_ECRAN_H`, `-DTAB5_ROTATION` build flags in both configurations (`tab5-ha-hmi.yaml`, `tab5-rendu-host.yaml`), with the Tab5's values as defaults in `tab5_geometrie.h` for the PC tests; `kCarteL`/`kCarteH` derive from `kEcranL`/`kEcranH`, and the pinball returns to `kRotationRepos`. `tests/test_geometrie_partagee.py` checks the C++ against the tokens **for every board**. The layout literals (positions and sizes of the widgets) are deliberately left alone.
- **Large fonts follow the board** (`roboto_32_b`, `roboto_45_b`, `roboto_55_b`, `roboto_130_b` in `tab5-styles.yaml`, and the theme fonts generated by `tools/gen_themes.py`): `size: ${ (N * (carte_police_echelle | float)) | round | int }`, which gives `N` on the Tab5.
- **The hardware the Waveshare lacks keeps its ids, as stubs.** The other packages (diagnostics, battery, energy saving, settings) reference the Tab5's power switches, battery gauge, headphone detect and RTC. Rather than make each of them conditional, `carte-waveshare-7b.yaml` turns them into template entities with `!extend`/`!remove` (no pin, optimistic switches, `update_interval: never` sensors), removes the RTC and its 24 h interval (which gets an `id`, `tab5_rtc_demarrage`, for that) and keeps the time-zone restore. The IMU is chosen in the root file: `tab5-imu.yaml` on the Tab5, `tab5-imu-absente.yaml` (the « Tap-to-Wake » switch only, without a name) elsewhere. The least intrusive option: the Tab5's packages do not change. The price: the blocks copied from `tab5-hardware.yaml` into the Waveshare package (logger, OTA, backlight output, media player…) can drift; `tests/test_carte_7b.py` keeps them equal.
- **The off-device render follows `tab5_carte`** (`geometrie-<carte>.yaml` in `tab5-rendu-host.yaml`, snapshot panel at the board's size). `rendu-host.yml` gets a second job, `rendu-7b`, which renders every screen at 1024×600 into a separate artifact (`rendu-1024x600`), informative only: the « identical » comparison stays the Tab5's, and the scripts keep the Tab5's coordinates.
- **CI compiles the Waveshare** (`build-carte-7b` in `esphome-tab5.yml`, same triggers as `build`, not a required check).

## Consequences

- On the Tab5 the resolved configuration is the same as before, except for the three build flags (equal to the header's defaults) and the `id` of the RTC interval — checked by comparing the configurations resolved by `esphome config` before and after, substitutions aside. The `config_hash` changes anyway: ESPHome hashes the substitutions block, which gains the `carte_*` keys.
- The project name (`axellum.tab5-ha-hmi`), `esphome: name` and `friendly_name` do not change with the board: a Waveshare compiled with the defaults would announce itself as a Tab5.
- The Waveshare's interface is not adapted: popups and the home screen overflow at 1024×600 until a later lot replaces the layout literals. A compile-time layout check that only holds at the Tab5's size (the five rows of the House popup fit in the card, `tab5_maison.cpp`) is guarded by `kMiseEnPageTab5` (`tab5_geometrie.h`, true on the Tab5): it stays strict there and lets the Waveshare compile.
- Not verified when written: nothing ran on a Waveshare (display, touch, audio, Wi-Fi co-processor); the pins come from a trial configuration that was compiled, never run.
- The Waveshare needs ESPHome 2026.9.1 or later (2026.9.0 aborts while starting the display of a P4 v3, esphome#18984; found on the board on 2026-10-14). A `min_version:` in the board package would be overridden by the root file's (2026.9.0, the Tab5's floor, read as is by CI) when packages are merged, so the board package lists `Tab5/ecran/carte_7b_version.h`, whose `static_assert` on `ESPHOME_VERSION_CODE` stops the build of the Waveshare under 2026.9.1.
